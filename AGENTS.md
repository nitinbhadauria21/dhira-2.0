## Cursor Cloud specific instructions

- **What this is:** a Next.js 15 / React 19 / TypeScript app with a real backend layer. It runs in two modes automatically:
  - **Offline/demo mode (default here):** with no real keys, Dhira uses a deterministic offline "brain" (`src/lib/localBrain.ts`) and saves to a local JSON file (`.data/dhira-store.json`, git-ignored). The full product works and is testable with **no keys** — this is how the cloud VM runs by default.
  - **Live mode (brain):** prefer `OPENROUTER_API_KEY` (`sk-or-v1-...`) as the central brain — all six agents go through `src/lib/anthropic.ts` → OpenRouter Anthropic-compatible API (`https://openrouter.ai/api`) with models `anthropic/claude-sonnet-4.5` / `anthropic/claude-haiku-4.5` (overridable via `DHIRA_MODEL_SONNET` / `DHIRA_MODEL_HAIKU`). Direct `ANTHROPIC_API_KEY` (`sk-...`) still works as a fallback. Without either → offline `localBrain`. Check `GET /api/status` → `liveBrain`.
  - **Live mode (data):** For Supabase: `NEXT_PUBLIC_SUPABASE_URL` + publishable/anon key turns on **Auth**; add `SUPABASE_SERVICE_ROLE_KEY` to also save data in Postgres (otherwise Auth works and data stays in `.data/`). Put real keys in `.env.local` (git-ignored). Check mode via `GET /api/status` (`supabaseAuth` / `supabaseStore`).
- **Architecture:** `src/agents/*` = the six agents (primary, monitor, escalation, moodTagging, memory, proactive) using the prompts in `Dhira_Agent_Prompts_Cursor.md`. `src/lib/chatFlow.ts` wires Escalation → Primary → Safety Monitor → mood/memory. `src/lib/store/*` is a pluggable store (`getStore()` picks Supabase or local file). Identity is a `dhira_session` cookie (`src/lib/auth.ts`) — email+password and phone+OTP via `/api/auth/*` (Supabase when configured, otherwise a local/dev auth that still creates real profiles). API routes live in `src/app/api/*`. Middleware protects `/home-dashboard`, `/chat-with-dhira`, `/profile`, `/timeline`.
- **Notifications:** Emergent schedules + delivers email/WhatsApp. Plain-English attach guide: `docs/emergent/EMERGENT_DEMO_DAY_WORKFLOW.md`. Dhira endpoints: `GET /api/notifications/due`, `POST /api/checkin`, `POST /api/notifications/weekly`, `POST /api/notifications/callback`. Without a webhook, status becomes `sent` with `providerMessageId: 'dev-simulated'`. WhatsApp only when `WHATSAPP_ENABLED=true`.
- **"My Dhira" page:** `/timeline` — weekly summary charts, searchable journal (`/api/journal`), chat history (`/api/chat-history`), notification inbox (`/api/notifications`). Nav "Timeline" tab points here.
- **Admin weekly:** `/api/admin/weekly` feeds mood-insights + overview (check-ins, valence, crisis, delivery, opt-ins, hour histogram).
- **Safety is server-driven:** crisis detection runs in the Escalation Agent + `src/lib/guardrails.ts` and always returns the Tele-MANAS 14416 hand-off; every outgoing message (chat + notifications) passes the Safety & Persona Monitor. Do not weaken this. Regex guardrails only ever scan Dhira's outgoing text, never the user's input.
- **Host (locked):** This product runs **only** in Cursor local — `npm run dev` → **http://localhost:4028**. Do not open Rocket (`*.builtwithrocket.new`) or any other external preview host. `GET /api/status` returns `"host":"cursor-local"` as a sanity check.
- **Claude artifact UI reference:** Visual copy/tokens live in `src/lib/artifactDesign.ts` and `references/Dhira-User-App-claude-artifact.html`. **Product rule:** new accounts must start blank (no demo mood/journal/chat seed). Home, chat, and memory banners only show real saved data; empty states use honest blank UI.
- **Talk to Dhira (ElevenLabs):** Widget in `AppLayout` shows a live voice log; **`GET /api/elevenlabs/session`** (signed-in cookie) returns a signed WebSocket URL or WebRTC token when `ELEVENLABS_API_KEY` is set on the server (required for auth-enabled agents). On call end it `POST`s `/api/elevenlabs/finalize` (session cookie) to save transcript → `chat_messages`, mood → `mood_logs` (`source: 'elevenlabs'`), memory, plus one persona reply via Primary/Monitor. Chat **Speak** uses `src/lib/browserSpeechRecognition.ts` (continuous until user taps Stop). Also keep migration `20260803_elevenlabs_mood_source.sql` applied on live Supabase.
- **CalmLink illustration pack:** designer cutouts live in `public/illustrations/` (served as `/illustrations/<file>`). Placement, halo CSS, and alt text are documented in `references/calmlink-assets/ASSETS.md`. Do not re-threshold PNG backgrounds — they use edge flood-fill so glossy highlights survive. Page-by-page UI reference: `references/calmlink-dc/` (`.dc.html` wins over CURSOR_SPEC when they disagree).
- **Live vs local auth gotcha:** if `.env.local` has real Supabase keys, `npm run dev` on `:4028` reports `supabaseAuth: true` and `/api/auth/signup` returns “Use Supabase sign-up in live mode” (browser uses Supabase client + `/api/auth/session` instead). For API-only local smoke without touching the live project, use the dummy-env spare-port command in the schema-drift note below.
- **Build passes even with type/lint errors** (`next.config.mjs` sets `ignoreBuildErrors`/`ignoreDuringBuilds`). Run `npm run type-check` and `npm run lint` separately to catch issues.
- **Lint is noisy:** many pre-existing `prettier/prettier` errors in committed code — not a regression unless in files you touched. `type-check` is clean.
- **Verifying the app:** sign-up (`/sign-up`) → onboarding → chat (`/chat-with-dhira`, real reply + saved) → `/timeline` (journal + weekly + inbox) → crisis via the "Test safety path" button → `/admin/safety` / `/admin/mood-insights` show logged events and weekly analytics. Dev OTP returns `devCode` in the JSON response when Supabase SMS is not configured. To reset demo data, delete `.data/dhira-store.json`.
- **Brand charts:** use `useChartBrand()` / `MOOD_PALETTE` from `src/lib/brand.ts` so Recharts stay on-brand in day and night themes.
- **Supabase setup (only for live cloud saving + real Auth):** run `supabase/schema.sql` in the Supabase SQL editor, then add the URL + anon + service-role keys to `.env.local`. See `supabase/DATA_MODEL.md`.
- **Schema drift caveat:** if the configured live Supabase returns `PGRST204`/`PGRST205` for branch fields such as `profiles.shift` or `notebook_entries`, do not work around it in app code. Either apply the committed Supabase migration/schema intentionally, or run a local-store smoke server with dummy Supabase env vars on a spare port (for example `NEXT_PUBLIC_SUPABASE_URL=dummy NEXT_PUBLIC_SUPABASE_ANON_KEY=dummy SUPABASE_SERVICE_ROLE_KEY= npx next dev -p 4128`) to validate UI/API flows without touching the external project.
